# PALETTE — 256 colours, one byte per pixel (D19)

Owner's decision (2026-09-19), after the side-by-sides in `tools/palette/out/`: **every image in the game
is palettised to 256 colours and stored at one byte per pixel.** The point is not memory. It is one look
across every ChatGPT generation, and lighting, time of day and effects done as palette tables instead of
redrawn art. This file is the contract between the cutter and the engine.

## The palettes

- **`story/palette/master.hex`** — the master palette, 256 lines of `#rrggbb`, shared by everything that
  can be on screen together in the field: tiles, stamps, walkers, portraits, UI art.
  **Index 0 is transparent. Index 1 is pure black, index 2 pure white.** 253 colours are free. The palette
  is organised as material ramps (variable length: long for skin, foliage, earth, stone, roof red; short
  for rare hues), shadows hue-shifted toward blue-violet and highlights toward yellow, because ramps are
  what make the light tables degrade gracefully. `master.pal.png` (256x1) and `master_swatch.png` (the
  image attached to ChatGPT prompts, one ramp per row) are generated from the hex file.
- **Cutscene panels get their own palette per scene** (`story/panels/<scene>.hex`, generated at cut time):
  they are never lit, never share the screen with the field, and their skies need the colours. Index 0 is
  still transparent.
- The palette is versioned by a `# version N` first line. Changing it means re-running `ingest --force`:
  every shipped image is re-derived from the raw returns archived in `story/sheets/`, so the palette can
  always be revised without regenerating art.

## Conversion (the cutter's last step)

Nearest colour in **Oklab**, exact (no coarse lookup grid for shipped art). **No dithering**, anywhere:
this art is cel-shaded over generator texture and every dither mode tested made it worse. Alpha is
**hard**: a pixel whose keyed alpha is under 0.5 becomes index 0, anything else takes its nearest opaque
colour after un-matting. Shipped files are **indexed PNGs** (colour type 3, PLTE + tRNS) — one byte per
pixel on disk, viewable anywhere. Applies to `atlas.png`, walkers, portraits, panels, props and the
parked 3D art alike. `./story_prompt.py palette apply <file>` converts anything by hand;
`palette build` rebuilds the master from the corpus; `palette check` fails any shipped image that holds a
colour outside its palette.

## In the engine

- An indexed PNG decodes through stb_image as RGBA; the loader maps each pixel back to its index by exact
  match against the palette (a 256-entry hash; alpha < 128 → 0) and uploads **`GL_R8`**, `GL_NEAREST`.
  A pixel that matches nothing is a build error in the art, logged once per file with a count, and takes
  the nearest colour.
- One **colormap** texture per palette: 256 wide, one row per (table, light level). Tables: `day`,
  `dusk`, `night`, plus effect tables (`flash`, `poison`, `stone`, …) as they are needed; 32 light levels
  per table, darkening in Oklab with a floor so the darkest level still reads (L never under ~0.15 for a
  colour that started above it). The colormap is generated by the tool into
  `story/palette/colormap.png` with a `colormap.json` naming the rows; the engine never computes colour.
- The tile shader fetches the four neighbouring indices, looks each up in the colormap row for that
  fragment's light, and blends the four **colours** bilinearly with premultiplied alpha (index 0 = zero),
  so full-resolution art still scales smoothly and hard-alpha edges still render soft. Light per fragment
  = the map's ambient (`light: <table> <level>` in a tmap's `## meta`) plus any point lights
  (`light x y radius level` triggers: lanterns, fires, windows at night); fractional levels blend the two
  adjacent rows.
- The cutscene player keeps drawing panels as ordinary RGBA textures (stb expands the indexed PNG); it
  needs no change.
- Palette cycling (water, fire, lamps) is a per-frame rewrite of a few colormap columns, declared in
  `story/palette/cycles.md` as `name: indices… @ fps`.
